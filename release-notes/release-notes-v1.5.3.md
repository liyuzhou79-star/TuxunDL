# TuxunDL 1.5.3 — 流量采样重做：切到后台照样记录

这一版修的是流量统计的老毛病：连着代理切到别的 App 去看视频、发消息，回来一看那段时间在图上是空白；首页速率还经常长时间挂 0 B/s，偶尔才跳一下。查清楚了，是采样方式的问题，这版把采样整个搬了家。

## 问题出在哪

- 采样原来是挂在主页上的：主页在，采样才在。主页被系统回收、或者人切到后台，采样就跟着停了
- 更隐蔽的一层：App 一退到后台，系统通道就会被解绑，主页那个每秒一次的循环拿不到新数据；就算后来补上一个迟到的数据点，旧逻辑里只要间隔超过 3 秒，那一整段就直接丢掉不记——所以后台那段时间在图上必然是空白
- 首页大按钮下面的速率是界面自己另外算的一套，和图表不是同一份数据；主页采样一卡住，它算出来的就一直是 0

## 修复内容

- **采样与界面解绑**：新做了一个应用级的采样器，App 启动时就位，只跟连接状态走——连接活着它就每秒采样，断开自动停。它自己持有和核心服务的连接，不再受主页存亡和前后台切换影响。切去别的 App 看视频、聊天，回来那段时间图上有连续曲线
- **迟到的数据不再丢弃**：进程被系统冻结一段时间后恢复时，冻结期间核心一直在转发、计数一直在涨。这段积累的流量现在按秒均匀摊开记成普通采样点，图上是一段与真实平均速率一致的平坦曲线——不再是空白，也不会把几分钟的流量挤成一座假山峰。今日总量、本周统计、连接时长照常累计这段流量
- **速率和图表同源**：首页速率、监控小图、全屏大图从此吃同一份采样记录，数字互相对得上，不再出现图在走、速率挂 0 的情况
- **顺带保留的原有口径**：连接质量探测（每 15 秒一次、断线/不佳判定）不动；核心计数器回落（断线重连）照旧记断线标记；冻结期间藏着的计数器回落不补记断线时刻（时间无从得知，不编造）
- **一个诚实的边界**：如果整个 App 进程被系统彻底杀掉（隧道是独立进程、还会继续跑），那段时间仍记不上，App 重新打开后从当时重新开始采样。进程内的采样已经做到极限，再往下要把采样搬进核心进程，留待以后

## 全屏页退出修复

- 流量全屏页：标题和右上角的关闭按钮固定在顶部，不再随页面滚动跑掉，滑到任何位置都能点到退出；页面整体避开状态栏和底部手势条，最下面的内容不再被手势条压住
- 更新全屏页（有新版本时弹出的那页）：底部的「立即更新」「稍后再说」原来正压在手势条上，点了没反应、像退不出去；现在整页避开手势条，两个按钮都能正常点

## 真机建议验一下

- 连上代理后，切到别的 App 看几分钟视频（或刷一会儿消息），再切回来打开流量监控和全屏图：那段时间应该是连续曲线（速率平稳的话是一段平坦的线），不再是空白或横线
- 连接状态下盯着首页大按钮下面的速率看一会儿：有流量时应该跟着跳动，不再长时间挂 0 B/s；速率和监控图对得上
- 全屏流量图滑到最下面：顶部的关闭按钮一直在、随时能退出；最下面的汇总卡完整显示、不被手势条挡住
- 有新版本弹出全屏更新页时：最下面的「稍后再说」能点、能正常退出
- 顺带看看：今日流量和本周统计有没有把后台那段算进去（应该算了）；桌面小部件的速率还正常刷新；连接分析里的断线红线、黄色不佳段还照常出现
